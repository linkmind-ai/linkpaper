## 1. 개요

### 1.1 문서 목적

본 문서는 그래프DB(Neo4j) 기반 RAG(Retrieval-Augmented Generation) 논문 Q&A 챗봇 서비스 'LinkPaper'의 프론트엔드에 대해, 현재까지 구현이 완료된 화면 구성과 기능을 기준으로 명세한다. 백엔드(FastAPI, 랭체인/랭그래프)가 아직 구축되지 않아 프론트엔드는 목업(Mock) 데이터와 시뮬레이션된 스트리밍으로 전체 기능을 동작시키며, 실제 백엔드 연동 시 필요한 API 계약(Contract)도 함께 정의한다.

### 1.2 시스템 개요

LinkPaper는 arXiv 논문을 검색·조회하면서 하나의 통합된 대화창에서 질문할 수 있는 웹 애플리케이션이다. 논문 내용 기반 질의응답, 인용 그래프를 활용한 심층 질의응답, 연구 흐름 탐색을 사용자가 직접 선택하지 않아도 백엔드가 질문 내용에 따라 자동으로 라우팅해 응답한다.

### 1.3 기술 스택

| ID | 항목 | 설명 | 구현 상태 / 비고 |
|---|---|---|---|
| FE-01 | 프레임워크 | React 18 + Vite 5, 패키지 매니저 pnpm | 완료 |
| FE-02 | 상태 관리 | Zustand (채팅/논문 상태, 토스트 상태 분리) | 완료 |
| FE-03 | 마크다운 렌더링 | react-markdown + remark-gfm | 완료 |
| FE-04 | 아이콘 | lucide-react | 완료 |
| FE-05 | 백엔드 연동(예정) | FastAPI, text/event-stream 기반 SSE 스트리밍 | 계약만 정의, 미구현 |
| FE-06 | 백엔드 RAG 파이프라인(예정) | LangChain + LangGraph, Neo4j(그래프DB) + Elasticsearch(벡터DB) | 프론트 영향 범위 아님 |

> ※ FE-05, FE-06은 백엔드 담당 항목으로, 본 문서에서는 연동 계약(5장)까지만 다룬다.

## 3. 전체 화면 구성

화면은 좌측부터 사이드바(Sidebar) · 논문 뷰어(Paper Viewer) · 채팅 패널(Chat Panel)의 3단 구조이며, 각 패널 사이의 경계를 마우스로 드래그해 너비를 조절할 수 있다. 채팅 패널은 남은 공간을 자동으로 채운다.

```
┌───────────────┬────╢────────────────────────┬────╢──────────────────────┐
│    Sidebar     │  ⋮ │      Paper Viewer         │  ⋮ │      Chat Panel        │
│  (드래그 가능)  │  ⋮ │      (드래그 가능)         │  ⋮ │  (남은 영역 자동 채움)   │
│                │  ⋮ │                            │  ⋮ │                        │
│ arXiv 검색      │  ⋮ │ 접기/펼치기 가능한 헤더     │  ⋮ │  메시지 스트리밍        │
│ 예시 질문       │  ⋮ │ (arXiv 메타데이터)         │  ⋮ │  인용 노드 칩           │
│                │  ⋮ │ 초록 / PDF 미리보기 탭     │  ⋮ │  흐름 스트립            │
└───────────────┴────╢────────────────────────┴────╢──────────────────────┘
                   드래그 핸들                     드래그 핸들
```

### 3.1 레이아웃 구조

| ID | 기능명 | 설명 | 구현 상태 |
|---|---|---|---|
| L-01 | 사이드바 (좌) | arXiv 논문 검색 및 목록, 예시 질문. 기본 너비 300px, 드래그로 220~440px 범위 조절 | 완료 |
| L-02 | 논문 뷰어 (중앙) | 선택된 논문의 메타데이터/초록/PDF를 표시. 기본 너비 760px, 드래그로 최소 380px 이상 조절 | 완료 |
| L-03 | 채팅 패널 (우) | 단일 대화 스레드. 고정 폭이 아닌 나머지 영역 전체를 채움(최소 360px) | 완료 |
| L-04 | 리사이즈 핸들 | 사이드바↔논문뷰어, 논문뷰어↔채팅 사이 드래그 바. 호버 시 보라색으로 강조 | 완료 |
| L-05 | 반응형 처리 | 화면 폭 1080px 이하에서는 3단을 세로로 쌓고 리사이즈 핸들을 숨김 | 완료 |

## 4. 기능 명세

### 4.1 통합 대화 파이프라인 (기능 선택 UI 없음)

과거에는 사이드바에서 'Paper Q&A' / 'GraphRAG-based Research Q&A' / 'Research Flow Exploration'을 사용자가 직접 선택하는 UI가 있었으나, **현재는 완전히 제거되었다.** 백엔드가 단일 파이프라인(랭그래프) 안에서 질문 내용을 분석해 (1) 일반 논문 QA, (2) 그래프 리트리버 기반 QA, (3) 연구 흐름 탐색 중 어떤 방식으로 답할지 내부적으로 라우팅하기 때문이다. 프론트엔드는 요청 시 별도의 `mode` 값을 전달하지 않으며, 어떤 경로로 처리되었는지는 응답 결과(`citations`/`flow` 유무)로만 사후에 판단한다.

| ID | 기능명 | 설명 | 구현 상태 |
|---|---|---|---|
| U-01 | 단일 대화 스레드 | 모드 구분 없이 하나의 채팅창에서 모든 질문(논문 내용, 관련 논문 비교, 연구 흐름 등)을 처리 | 완료 |
| U-02 | 통합 예시 질문 | 과거 모드별로 나뉘어 있던 예시 질문을 하나의 목록으로 통합해 사이드바에 노출, 클릭 시 입력창에 자동 채움 | 완료 |
| U-03 | 라우팅 결과의 투명한 표시 | 그래프 리트리버가 사용된 응답에는 인용 칩·배지를, 연구 흐름 경로로 처리된 응답에는 흐름 스트립을 자동으로 표시해 백엔드 라우팅 결과를 사용자에게 드러냄 | 완료 |

> ※ M-01~M-04(기능 선택), qa/research-flow 모드 구분은 v1.3에서 폐기되었다. 이전 버전과의 차이는 2장 버전 이력 참고.

## 5. 백엔드 연동 명세 (API Contract)

현재 프론트엔드는 `.env`의 `VITE_USE_MOCK` 값으로 목업/실제 백엔드를 전환하도록 구성되어 있다(`src/api/index.js`). 아래 계약대로 백엔드가 구현되면 프론트엔드 컴포넌트 코드 수정 없이 연동된다.

### 5.1 `GET /api/papers/search`

arXiv 논문 검색. 백엔드가 export.arxiv.org 를 호출해 결과를 정규화하여 반환한다(CORS/레이트리밋 관리 및 그래프DB 적재 전처리 목적).

| 필드 | 타입 | 설명 |
|---|---|---|
| `q` | string (query param) | 검색어. 비어있으면 기본/최근 논문 목록 반환 |
| `id` | string | arXiv 논문 ID (예: 1706.03762) |
| `title` | string | 논문 제목 |
| `authors` | string | 저자 목록(표시용 문자열) |
| `year` | number | 발행 연도 |
| `categories` | string[] | arXiv 분류 카테고리 (예: cs.CL) |
| `summary` | string | 초록(abstract) |
| `pdfUrl` | string | PDF 다운로드/임베드 URL |
| `arxivUrl` | string | arXiv 논문 상세 페이지 URL |

### 5.2 `POST /api/chat/stream`

요청 본문에 **`mode` 필드가 없다.** 어떤 방식(일반 QA / 그래프 리트리버 QA / 연구 흐름 탐색)으로 답할지는 백엔드의 랭그래프 라우팅 노드가 질문 내용을 보고 전적으로 결정한다.

**요청 본문 (JSON):**

| 필드 | 타입 | 설명 |
|---|---|---|
| `paperId` | string | 현재 선택된 논문의 arXiv ID |
| `message` | string | 사용자 질문 |
| `history` | `Array<{role, content}>` | 이전 대화 이력(직전 스트리밍 중 메시지는 제외) |

**응답:** `text/event-stream`, 각 이벤트는 `data: {json}\n\n` 형식.

| type | payload | 설명 |
|---|---|---|
| `token` | `{ text }` | 답변 텍스트 조각(스트리밍 렌더링용) |
| `citations` | `{ citations: [{id,label,relation}] }` | 그래프 리트리버가 실제로 사용된 경우에만 전송 → 프론트에서 인용 칩 및 배지 표시 |
| `flow` | `{ flow: [{stage,label}] }` | 연구 흐름 경로로 라우팅된 경우에만 전송, 선행/현재/후속 연구 노드 |
| `done` | `{}` | 스트림 종료 |
| `error` | `{ message }` | 오류 발생, 프론트에서 오류 메시지 및 토스트로 노출 |

> ※ 그래프 검색을 사용한 경우에만 `citations` 이벤트를, 연구 흐름 경로로 처리된 경우에만 `flow` 이벤트를 전송해야 프론트의 자동 배지·흐름 스트립 로직이 정상 동작한다.
